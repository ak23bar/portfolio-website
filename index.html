Pocket Brain - Offline Quantized LLM Assistant

Status: Active Development

GitHub: ak23bar/Pocket-Brain

Authors: Akbar Aman & Luke Abraham, 2026

Project Overview

Pocket Brain is a portable, fully offline conversational assistant for private brainstorming on constrained hardware. It targets CPU-only execution with a strict memory budget of ≤8GB RAM while maintaining predictable latency. The system integrates existing quantized open-weight LLMs through a local API, exposing structured interaction modes that improve output quality without increasing computational requirements.

Pocket Brain v1 is scoped as a personal, single-user tool. Design decisions prioritize determinism, portability, and explicit resource control over feature breadth. This is a systems engineering project focused on orchestrating quantized inference, enforcing bounded context growth, and providing structured prompting.

Core Constraints

  • Offline-only: No outbound network calls required for inference or interaction
  • CPU-only: Runs without GPU acceleration
  • ≤8GB RAM: Total runtime memory must stay within this budget
  • Portable local storage: Models and session artifacts reside on local disk/SSD

Architecture Components

  • Clients: Web UI (HTML/JS) and CLI provide user interfaces
  • API Gateway: Exposes /chat, /reset, /save endpoints
  • Backend Orchestrator: Enforces modes, context caps, session state, and truncation policies
  • Inference Engine: Quantized CPU-only model execution (GGUF format)
  • Local Storage: Persists transcripts, session metadata, and model artifacts

Conversation Memory & Context Management

Large Language Models are stateless at inference time. Conversational "memory" is implemented by the application layer by resending a bounded subset of the transcript along with each new user message. Pocket Brain enforces a sliding window of the last N user-assistant exchanges (e.g., N=10), dropping older turns from the active inference context while persisting them to disk.

Interaction Modes

Pocket Brain enforces one mode per session, selected at session creation. Mode scoping stabilizes behavior on smaller models by avoiding multi-mode instruction stacking.

  • perspectives: Generate alternative viewpoints and angles
  • risks: Identify weaknesses, failure modes, and unknowns
  • next_steps: Produce actionable next actions and priorities

Model Strategy (v1)

Pocket Brain does not train or fine-tune models. It integrates existing open-weight, instruction-tuned models that have been quantized (GGUF format) for efficient CPU inference.

  • Qwen2.5 Instruct (3B): Default - balanced quality/speed, strong instruction following
  • Phi-3 Mini (3.8B): Alt-fast - quick iteration, low memory pressure
  • Mistral Instruct (7B): Optional - higher coherence, better complex reasoning

Implementation Milestones

  • Milestone 1: End-to-end skeleton with API service, session creation, and transcript auto-save
  • Milestone 2: Enforced constraints including fixed mode per session and sliding window history
  • Milestone 3: Usability improvements with Web UI/CLI parity and "New Chat" rollover

Technical Stack

  • Languages: Python (backend/orchestration), HTML/JavaScript (web UI)
  • Models: Quantized GGUF models (Qwen2.5, Phi-3, Mistral)
  • Inference: CPU-only quantized LLM execution
  • Architecture: Local API service, session management, context truncation
  • Storage: Local disk persistence for transcripts and metadata

What Pocket Brain is NOT

  • Not a cloud service or multi-user platform
  • Not a training or fine-tuning framework
  • Not a production-ready consumer product
  • Not a GPU-dependent system
  • No model training, fine-tuning, or RAG in v1
